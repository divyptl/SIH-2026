# SatQuery AI — frontend

The web app for SatQuery AI: upload satellite images, ask a question in English
or any of 22 Indian languages, and read the answer next to the evidence marked
on the image. Also hosts `/demo`, an animated walkthrough of the pipeline for
presentations.

React 19 + Vite + TanStack Router (file-based routes), shadcn/ui on Base UI,
Tailwind CSS 4, Motion, react-i18next.

## Run

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

The app calls the FastAPI backend at `VITE_API_BASE_URL` (default
`http://localhost:8000`); see [../backend/README.md](../backend/README.md). The
`/demo` page plays back recorded runs and works without the backend.

```bash
pnpm build        # production build
pnpm lint         # eslint
pnpm format       # prettier --write + eslint --fix
pnpm check        # prettier --check
```

Route files live in `src/routes`; `src/routeTree.gen.ts` is generated by the
router plugin while `pnpm dev` runs (or `npx tsr generate`).

### `/demo` — how it works

`routes/demo.tsx` is a presenter-ready walkthrough, one per input type, each
playing back a **real recorded run** of the pipeline:

| Walkthrough      | File                            | Specialist                                                                 |
| ---------------- | ------------------------------- | -------------------------------------------------------------------------- |
| Before and after | `components/demo/change.tsx`    | Change-VQA — Assam flood, asked in Hindi                                   |
| One image        | `components/demo/grounding.tsx` | Grounding — storage tanks, checked against the DIOR-RSVG label             |
| Optical + radar  | `components/demo/fusion.tsx`    | Optical–SAR fusion — water share checked against a Sen1Floods11 hand label |

`components/demo/kit.tsx` holds the shared steps (ask and translate, check the
images, pick the task, answer with a timeline of every stage) and animation
helpers; `scenario.ts` defines a walkthrough. The recorded API responses are the
`*-run.json` files beside them; their images and masks are in `public/demo/`.

Presenter keys: Space pause/play, ←/→ or PageUp/PageDown (clickers) step,
Shift+←/→ switch walkthrough, 1–9 jump to a step, R replay, F enter/leave full
screen. The TanStack devtools button is hidden on this route.

To add a walkthrough, record a run (POST to `/api/analyse`, add the question as
`query`, move the data URIs to `public/demo/`), write a `Scenario` using the kit,
and add it to `SCENARIOS` in `routes/demo.tsx`.

## Design

- **Colours:** the shadcn tokens in `src/styles.css` (neutral cool grey, light and
  dark). The one hue is fuchsia, reserved for change and the model's own marks.
- **Type:** Schibsted Grotesk for headings (`font-heading`), Poppins for body
  text; other Indic scripts fall back per glyph to Nirmala UI / Noto.
- **Utilities** in `styles.css`: `graticule` (the faint map grid behind image
  areas) and `animate-scan` (the analysis scan line). `viewfinder.tsx` draws the
  corner marks around image areas.
- Motion respects the system "reduce motion" setting throughout.

## Translations

UI strings live in `src/locales/<code>.json`; `en.json` is the source. After
adding or changing English strings, fill the other 22 languages with the
backend's IndicTrans2 script (only missing keys are translated):

```bash
cd ../backend
uv run python -m scripts.translate_locales
```

Strings containing terms the model mangles (GeoTIFF, SAR, …) are rejected and
fall back to English; the script lists them.
